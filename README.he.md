# ערכת המפקח

ניהול פרויקטים שסוכני AI בונים, בלי לקרוא קוד.

סוכן אחד בונה.
סוכן אחר מפקח: מכיר אתכם, מתרגם לכם כל שאלה של הבונה,
עוזר לכם להחליט, ובודק את העבודה לפני שאתם שומעים "סיימתי".

## הרעיון

מי שבנה פעם בית מכיר את זה.
יש קבלן מבצע, עם מנהל עבודה וצוותים.
ויש מפקח בנייה שעובד בשבילכם.

- **המפקח** יושב בתיקייה הזו. מכיר אתכם ואת כל הפרויקטים שלכם, ונשאר איתכם בין פרויקטים.
- **הקבלן** הוא סשן סוכן נפרד בתיקייה של כל פרויקט. בפרויקט מסודר הוא כותב אפיון, מפת דרכים, תכנית לכל שלב, וסיכום בסוף כל סשן. בפרויקט מהיר הוא בונה ישר מהבריף.
- **אתם** המנכ"ל. מדברים עם המפקח, וכל החלטה היא שלכם. ב-Claude Code המפקח והקבלן מעבירים הודעות ישירות זה לזה, כך שכבר לא צריך להעתיק ולהדביק. כל מה שהוא החלטה עדיין מחכה ל"כן" שלכם.

## מה יש בפנים

קבצי טקסט בלבד. בלי התקנות, בלי פייתון, בלי חשבונות.

| פקודה | מה היא עושה |
|-------|-------------|
| `/add-project` | פרויקט חדש (המפקח כותב לקבלן את הבריף הראשון) או חיבור פרויקט קיים |
| `/translate` | מדביקים שאלה של הקבלן, ומקבלים אותה בשפה פשוטה, עם אפשרויות והמלצה, ותשובה מוכנה להדבקה |
| `/check-plan` | לפני שמאשרים אפיון, מפת דרכים או תכנית: הם בתוך מה שביקשתם? יש בהם את ההחלטות שקיבלתם אחרי שנכתבו? |
| `/inspect` | אחרי שלב: המפקח מריץ את הבדיקות בעצמו, קורא את השינוי מול האפיון ורושם ביומן |
| `/watch` | בזמן שהקבלן עובד: מה השתנה, והאם צריכים אתכם. פעם אחת, או כל כמה דקות |
| `/site-report` | איפה עומד כל פרויקט, ומה מחכה לכם |

לא חייבים לזכור אותן.
מדביקים שאלה של הקבלן, והמפקח מתרגם.
אומרים "הוא סיים", והמפקח בודק.
שואלים "מה המצב?", והמפקח מסתכל.

## תמיד יודעים איפה הדברים עומדים (חדש בגרסה 1.1)

- הקבלן שולח עדכון התקדמות קצר אחרי כל חלק עבודה. המפקח הופך אותו לשורה אחת בשבילכם: מה נבנה, והאם צריכים אתכם: לא כרגע, בקרוב, או עכשיו.
- בזמן שהקבלן עובד, המפקח יכול להסתכל על הפרויקט כל כמה דקות (בוחרים כל כמה בהקמה) ולספר לכם מה השתנה, כולל כשהקבלן תקוע ומחכה לאישור שלכם בחלון שלו.
- בכל בריף המפקח ממליץ איך הקבלן מחלק את העבודה: לבד, עם סוכני עזר במקביל, או כמתזמר שמריץ כל שלב בסוכן עזר חדש.

## שני מסלולים: מסודר או מהיר (חדש בגרסה 1.1)

לא כל פרויקט צריך את כל הניירת.
משחק קטן לא צריך לחכות לאפיון ולמפת דרכים.
מערכת שמחזיקה נתונים של לקוחות כן צריכה.
בכל פרויקט חדש המפקח שואל איך אתם רוצים לעבוד, וממליץ:

| | **מסודר** | **מהיר** |
|---|---|---|
| מתאים ל | מישהו אחר ישתמש בזה, נתונים אמיתיים של אנשים, כסף, שליחה או פרסום, עלייה לאוויר, עבודה של כמה סשנים | משחק או אפליקציה פשוטה, כלי חד-פעמי, אב-טיפוס, תיקון בודד, משהו שרק אתם משתמשים בו |
| מה הקבלן כותב | אפיון, מפת דרכים, תכנית לכל שלב, סיכומים | קובץ מצב וסיכומים קצרים. הבריף הוא האפיון |
| עצירות לאישור | אחרי האפיון, אחרי מפת הדרכים, לפני כל שלב | אין. הוא בונה ומדווח "סיימתי" |
| מה המפקח בודק | כל תכנית לפני שמאשרים, וכל שלב אחרי | את התוצאה, מול הבריף |

פרויקט מהיר שגדל? המפקח ימליץ לעבור למסלול המסודר. ההחלטה שלכם.

## קו ישיר בין המפקח לקבלן (חדש בגרסה 1.1)

הסקיל `contractor-link` מאתר את החלון של הקבלן במחשב ומדבר איתו ישירות.
הוא שולח את הבריף ואת הבדיקות.
הקבלן מחזיר "סיימתי" בסוף כל שלב, והמפקח בודק בעצמו.

אתם קובעים כמה הוא שולח בלי לשאול:

| מצב | מה קורה |
|-----|---------|
| **רגיל** (מומלץ) | שאלות, בדיקות ובקשות תיקון יוצאות בלי לשאול, ואתם מקבלים עדכון מה נשלח. כל מה שהוא החלטה מחכה ל"כן" שלכם |
| **מחמיר** | אתם רואים כל הודעה לפני שהיא יוצאת |
| **הדבקה** | בלי קו ישיר: המפקח כותב, אתם מעתיקים לקבלן, כמו בגרסה 1.0 |

החלטה היא תמיד שלכם, בכל מצב:
אישור אפיון או תכנית, תשובה לשאלות שהקבלן שאל אתכם, שינוי במה שנבנה, מחיקה, הוצאת כסף.
בוחרים מצב בהקמה, ואפשר לשנות בכל רגע, פשוט אומרים למפקח.

## מה צריך

סוכן שעובד על תיקיות במחשב:
Claude Code (באפליקציית Claude, בלשונית Code, או בטרמינל),
או Antigravity, Cursor, Codex וכדומה.
חלון הצ'אט הרגיל לא יודע לפתוח תיקייה.

לקו הישיר צריך Claude Code בשני החלונות, על אותו מחשב,
בגרסה 2.1.234 ומעלה בווינדוס (2.1.224 במק ובלינוקס).
שני החלונות במצב שמבקש אישור לפני פעולה (ברירת המחדל הרגילה).
כל השאר עובד במצב הדבקה.

**מה עובד איפה.** הערכה היא קבצי טקסט, אז השיטה עובדת בכל כלי סוכנים.
Claude Code מוסיף את האוטומציה מסביב:

| | Claude Code | כלי סוכנים אחרים |
|---|---|---|
| מפקח, בריפים, שני מסלולים, בדיקות, יומן | כן | כן |
| הודעות בין המפקח לקבלן | ישירות | אתם מעתיקים ומדביקים |
| עדכוני התקדמות | נשלחים למפקח | נכתבים בקובץ המצב של הקבלן, המפקח קורא אותם |
| עדכון מצב כל כמה דקות | כן (`/loop`) | כשאתם שואלים |

## התקנה

1. **מחלצים את קובץ הזיפ** למקום נוח, למשל תיקיית `projects` בכונן.
2. **פותחים את התיקייה** עם הסוכן.
3. **כותבים לו:** `read README.md and SETUP.md, then start the setup`.
   הוא שואל כמה שאלות עליכם (בערך עשר דקות) ומחבר את הפרויקט הראשון.
4. **מפעילים מחדש את הסשן** פעם אחת, כדי שהפקודות ייטענו.

מעכשיו: בכל עבודה על פרויקט, פותחים את התיקייה הזו ומדברים עם המפקח.

## יום עבודה

שני חלונות, זה לצד זה.
משמאל המפקח (התיקייה הזו). מימין הקבלן (תיקיית הפרויקט).
מדברים עם המפקח.

נותנים לשני החלונות שם, פעם אחת:
`/rename supervisor` משמאל, `/rename <project>-contractor` מימין.
כך הם מוצאים זה את זה גם מחר.

עם קו ישיר: המפקח והקבלן מדברים ביניהם, אתם רואים הכל בשני החלונות, ונכנסים כשהמפקח מביא לכם החלטה.
במצב הדבקה: ההודעות שהמפקח כותב לקבלן, מדביקים מימין.
הקבלן שאל משהו שלא ברור לכם? מעתיקים אותו למפקח.
הקבלן אמר שסיים? אומרים למפקח "הוא סיים".

## שדרוג מגרסה 1.0

בתיקיות `me`, `projects` ו-`supervision-log` יש את המידע שלכם. שומרים אותן.

1. מחלצים את הזיפ החדש לתיקייה חדשה.
2. מעתיקים לתיקיית המפקח הקיימת, עם החלפה: `CLAUDE.md`, `SETUP.md`, `AGENTS.md`, שני קבצי ה-README, התיקייה `templates` והתיקייה `.claude`.
   לא מעתיקים את `me`, `projects` ו-`supervision-log`.
3. מפעילים מחדש את הסשן. בפעם הראשונה שהמפקח צריך לשלוח הודעה לקבלן, הוא מסביר את שלושת המצבים ושואל מה אתם מעדיפים. בפעם הראשונה שהוא מתחבר לקבלן, הוא שואל כל כמה זמן אתם רוצים עדכון מצב, ובאיזה מסלול נמצא כל פרויקט קיים.
4. לכל פרויקט שכבר תחת פיקוח, המפקח יציע לעדכן את סעיף המפקח בקובץ `CLAUDE.md` של הפרויקט. אומרים כן.

## ארבעה כללים

1. לכל פרויקט יש מסלול, ואתם בוחרים אותו. במסודר: אפיון, מפת דרכים וסיכום בסוף כל סשן. במהיר: הבריף הוא האפיון. את זה המפקח קורא.
2. המפקח מנהל יומן פיקוח משלו, עם תאריך: מה נמסר, מה נבדק, מה עוד פתוח.
3. המפקח קורא את תיקיית הפרויקט. הוא לא בונה בה.
4. מה שלא באפיון לא נבנה. הוא נכנס לרשימת המתנה.
